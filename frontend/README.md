# RepairFlow — фронтенд

Vue 3 + TypeScript + Tailwind CSS 4, сборка на Vite.

## Запуск

```bash
npm install
npm run dev            # http://localhost:5173
```

Бэкенд поднимается отдельно из корня репозитория (`docker compose up`) и слушает http://localhost:5080 —
`.env` для этого не нужен: запросы к `/api`, `/hubs` и `/health` перенаправляет прокси из `vite.config.ts`.

```bash
npm run build       # типы + продакшн-сборка в dist/
npm run type-check  # только проверка типов
npm run preview     # локальный просмотр собранной версии
```

## Структура

```
src/
  api/          типы контрактов, axios-клиент, обёртки эндпоинтов
  i18n/         словари en/ru и типизированная функция t()
  realtime/     подключение к SignalR-хабу (протокол MessagePack)
  stores/       Pinia: авторизация и тосты
  router/       маршруты с guard'ами по ролям и направлением переходов
  lib/          форматирование, тона статусов, тема, состояние верхней панели
  components/   ui — элементы дизайн-системы, layout — оболочка, orders и dashboard — прикладные
  views/        экраны
```

## Что стоит посмотреть в коде

**`i18n/` — локализация, которую проверяет компилятор.** Ключ — путь в английском словаре, тип
ключей выводится из него же. Опечатка в ключе или фраза, забытая в `ru.ts`, — ошибка сборки, а не
пустая строка на экране. Множественное число выбирает `Intl.PluralRules`.

**`style.css` — темы на токенах.** Компоненты используют смысловые утилиты (`bg-surface`,
`text-ink-2`), тема подменяет CSS-переменные за ними. Выбор темы и языка применяется ещё до загрузки
бандла — скриптом в `index.html`, поэтому тёмная тема не мигает белым.

**`api/client.ts` — тихое обновление токена.** Access-токен живёт только в памяти вкладки: класть его в
localStorage нельзя, оттуда его достанет любой XSS. Долгоживущий refresh лежит в httpOnly-куке, поэтому
после F5 сессия поднимается запросом `/auth/refresh`. Перехватчик ловит 401, обновляет пару токенов и
повторяет исходный запрос — параллельные запросы при этом ждут одно обновление, а не устраивают гонку.

**`realtime/orderEvents.ts` — живые обновления.** Подписка на события конкретной заявки по WebSocket с
бинарным протоколом MessagePack. Если хаб недоступен, страница просто работает как обычная — уведомления
это бонус, а не условие работы.

**`components/orders/StatusTimeline.vue` — шкала статусов.** Путь заявки нарисован временной шкалой:
пройденные шаги залиты цветом своего статуса, текущий пульсирует, будущие контурные, под каждым — дата и
автор перехода из истории.

**`components/dashboard/OrdersChart.vue` — график без графической библиотеки.** Инлайновый SVG: две серии,
линии 2px, сплошная волосяная сетка, подписи на концах линий с выносками при схлопывании, наведение с
подсказкой и таблица-двойник для тех, кому цвет недоступен. Пара цветов проверена на различимость при
дальтонизме.

## Деплой

`vercel.json` описывает сборку и четыре правила, и порядок в них значимый.

Первые три разворачивают `/api/*`, `/hubs/*` и `/health` на бэкенд в Render. Смысл не в удобстве:
браузер должен видеть API на том же домене, что и приложение, иначе кука с refresh-токеном
становится сторонней — а сторонние куки Safari режет давно, Chrome и Edge подтянулись. Сессия
в таком случае живёт до первой перезагрузки страницы. Ту же схему повторяет прокси в
`vite.config.ts`, чтобы разработка и продакшн вели себя одинаково.

Последнее правило отдаёт `index.html` на любой другой путь — чтобы прямая ссылка на `/orders/<id>`
открывалась, а не отдавала 404: маршрутизация у SPA происходит в браузере. Статические файлы из
`dist` это правило не перехватывает — Vercel сначала ищет файл на диске и только потом применяет
rewrites.

Блок `headers` отключает кеширование проксируемых ответов: список заявок у клиента и у менеджера
разный, и отдавать один другому нельзя.

Схема `vercel.json` строгая и не допускает посторонних ключей, комментариев в нём быть не может —
поэтому пояснение живёт здесь.

## Дизайн

Современный flat на индиго, поведение — как у мобильного приложения: нижнее меню, шторки,
крупные заголовки, стек экранов. Токены, тона статусов и правила — в
[`../docs/design-system.md`](../docs/design-system.md). Новые экраны собираются из компонентов
`components/ui` и `components/layout`.
