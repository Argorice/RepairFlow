# Публикация RepairFlow

Проект состоит из трёх частей, и живут они в трёх разных местах. Одним пушем это не поднимется:
репозиторий надо один раз связать с двумя площадками и передать им четыре переменные окружения.
Дальше — да, каждый `git push` в `main` пересобирает и выкатывает обе половины.

| Что | Где | Бесплатно | Оговорка |
|---|---|---|---|
| Код | GitHub | да | — |
| PostgreSQL | [Neon](https://neon.com) | 0.5 ГБ, бессрочно | компьют засыпает через 5 минут, просыпается мгновенно |
| Бэкенд | [Render](https://render.com) | 750 инстанс-часов в месяц | сервис засыпает через 15 минут, холодный старт ~1 минута |
| Фронтенд | [Vercel](https://vercel.com) | план Hobby | только некоммерческое использование |

Карта ни на одной из трёх площадок не нужна.

---

## Шаг 0. Репозиторий

Создайте на GitHub пустой репозиторий **repairflow** — без README и `.gitignore`, они уже есть в
проекте, — и отправьте туда код:

```powershell
cd C:\Programming\RepairFlow
git remote add origin https://github.com/<логин>/repairflow.git
git push -u origin main
```

Перед первым пушем загляните в `git status`: в репозиторий не должны попасть `.env`,
`node_modules`, `bin`, `obj`, `dist` и папка `storage` с загруженными файлами. Всё это перечислено
в `.gitignore`, но проверить стоит — секрет, попавший в историю, оттуда уже не убрать.

---

## Шаг 1. База данных

Она уже создана — проект **RepairFlow** в Neon, регион Frankfurt, база `neondb`.
Строка подключения: **Dashboard → Connect → .NET**. Приводится к такому виду:

```
Host=<endpoint>-pooler.<region>.aws.neon.tech;Database=neondb;Username=neondb_owner;Password=<пароль>;SSL Mode=Require;Channel Binding=Require;Maximum Pool Size=10;No Reset On Close=true
```

`No Reset On Close=true` нужен потому, что Neon отдаёт соединения через PgBouncer в transaction-режиме.

Схему накатывать не надо: при первом старте приложение само создаст таблицы и зальёт демо-данные.

## Шаг 2. Бэкенд на Render

1. **New → Blueprint**, выберите репозиторий. Render найдёт `render.yaml` в корне.
2. Он спросит значения двух переменных:
   - `ConnectionStrings__Default` — строка из шага 1;
   - `Cors__Origins__0` — адрес фронтенда. Его вы узнаете только на шаге 3, поэтому пока введите
     заглушку `https://example.com` и вернитесь сюда после деплоя фронта.
3. `Jwt__Key` Render сгенерирует сам — вам его видеть не нужно.
4. Первая сборка Docker-образа занимает 5–10 минут. Следите за логом: строка
   `Демо-данные готовы` означает, что база заполнена.

Адрес будет вида `https://repairflow-api.onrender.com`. Проверьте:

- `https://<адрес>/health` → `{"status":"ok"}`
- `https://<адрес>/scalar/v1` → документация API

## Шаг 3. Фронтенд на Vercel

1. **Add New → Project**, выберите тот же репозиторий.
2. **Root Directory** обязательно поменяйте на `frontend` — иначе Vercel будет собирать корень
   репозитория и не найдёт `package.json`.
3. Framework Vercel определит сам (Vite), команды подставит из `frontend/vercel.json`.
4. Добавьте переменную окружения:

   ```
   VITE_API_URL = https://repairflow-api.onrender.com
   ```

   Она читается на этапе сборки, поэтому после её изменения нужен **Redeploy**, а не просто перезапуск.

### Если внешний адрес отдаёт 502

502 означает, что балансировщик Render не смог достучаться до приложения. Смотреть надо не в
**Logs** (они пустые, когда процесса нет), а во вкладку **Events** и в лог сборки внутри **Deploys**.

По [документации Render](https://render.com/docs/troubleshooting-deploys#502-bad-gateway) причина
почти всегда одна из двух: процесс слушает `localhost` вместо `0.0.0.0` либо занял не тот порт —
без переменной `PORT` Render ждёт **10000**. В нашем образе оба условия выполнены: приложение
стартует с `--urls http://0.0.0.0:${PORT:-10000}`.

Заголовки CORS к 502 отношения не имеют: упавшее приложение не отдаёт вообще никаких заголовков,
и браузер сообщает об этом как о нарушении CORS. Пока `/health` не отвечает `{"status":"ok"}`,
настройки CORS менять бессмысленно.

## Шаг 4. Связать половины обратно

Фронт и API живут на разных доменах, значит кука с refresh-токеном — кросс-сайтовая. Чтобы браузер
её принял, нужны три вещи, и все три уже настроены, кроме одной переменной:

1. В Render поменяйте `Cors__Origins__0` на настоящий адрес Vercel и нажмите
   **Manual Deploy → Deploy latest commit**.

   Звёздочку сюда писать нельзя: браузер отвергает `Access-Control-Allow-Origin: *` вместе с куками,
   а refresh-токен ездит именно в куке. Если очень нужно временно разрешить любой источник —
   оставьте переменную пустой: тогда приложение отражает Origin запроса, и это с куками работает.
2. `Jwt__CrossSiteCookies=true` уже стоит в `render.yaml`.
3. HTTPS обе площадки дают сами.

Если после этого вход работает, а через 15 минут вас выкидывает — значит тихое обновление токена
не проходит: проверьте, что адрес в `Cors__Origins__0` совпадает с адресом в браузере до символа,
включая отсутствие слэша в конце.

## Шаг 5. Проверка перед тем, как кидать ссылку

- [ ] Открывается страница входа, три демо-кнопки на месте
- [ ] «Войти как менеджер» → дашборд с графиком и заполненными счётчиками
- [ ] «Войти как клиент» → в списке только свои заявки
- [ ] Открыть карточку заявки, поменять статус — появилась запись в истории
- [ ] Перезагрузить страницу (F5) — не выкидывает на вход
- [ ] Открыть демо в приватном окне — работает без вашей сессии
- [ ] Ссылка с фильтрами (`/orders?status=InProgress`) открывается напрямую

## Про сон бесплатного сервиса

Render усыпляет бесплатный сервис после 15 минут без трафика, и первый запрос после сна ждёт
около минуты. Для демо в портфолио это худшая из возможных первых секунд.

Что с этим сделано и что можно сделать:

**Уже в коде.** Страница входа при открытии дёргает `/health`, то есть будит сервер, пока человек
читает текст и выбирает роль. Если за 2,5 секунды ответа нет, под кнопками появляется честная
строка «Демо-сервер просыпается после простоя». Это ничего не стоит и убирает эффект «сайт сломан».

**Опционально.** В `.github/workflows/keepalive.yml` лежит выключенный воркфлоу, который пингует
сервис раз в 10 минут. Чтобы включить, задайте переменную репозитория `API_HEALTH_URL`
(Settings → Secrets and variables → Actions → Variables) со значением `https://<адрес>/health`.

Два предупреждения, прежде чем включать:

- Постоянно работающий сервис расходует почти весь месячный лимит: в месяце 744 часа при
  бесплатных 750. Второй сервис на том же аккаунте уже не поместится.
- GitHub отключает расписания в репозиториях, где 60 дней не было активности. Раз в пару месяцев
  придётся заглядывать.

## Что на бесплатном тарифе работает не полностью

**Загруженные файлы исчезают при каждом деплое.** У бесплатного сервиса Render нет постоянного
диска, а вложения складываются в `/app/storage`. Для демо это не страшно — сидер всё равно
пересоздаёт данные, — но заказчику, который загрузит фото и вернётся завтра, стоит об этом сказать.
Лечится переносом файлов в S3-совместимое хранилище: у `IFileStorage` ровно четыре метода,
меняется одна реализация.

**База спит.** Neon усыпляет компьют через 5 минут простоя, но просыпается он за доли секунды —
на фоне минутного старта Render этого не заметно.

**Vercel Hobby — только для некоммерческого использования.** Портфолио под это подходит,
коммерческий проект клиента — нет.
